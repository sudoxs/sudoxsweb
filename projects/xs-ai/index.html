OVERVIEW

What Is XS-AI

XS-AI is a pure-Python pentest orchestrator that pairs AI reasoning with human judgment. It runs on Kali Linux and talks to an Ollama instance on your Windows host — or directly to OpenAI / Anthropic cloud APIs.

The AI suggests commands. You approve, edit, or skip every one. Nothing executes without explicit operator consent. Session state, findings, and command history are saved automatically so you can resume any engagement.

03
CAPABILITIES

Features

FEAT_01

Human-in-the-Loop

Every command requires explicit operator approval. Edit, skip, or override any AI suggestion before it touches the target.

FEAT_02

Multi-Backend AI

Local Ollama models by default. Swap to OpenAI or Anthropic Claude with a single flag for more capable reasoning.

FEAT_03

14 Service Enumerators

Port-aware enumeration for FTP, SSH, SMTP, DNS, HTTP, SMB, NFS, MSSQL, MySQL, RDP, WinRM, SNMP, Redis, and LDAP.

FEAT_04

Role Mapping

Assign different AI models to different phases. Route recon to a planner, access to an analyzer — full control over your model chain.

FEAT_05

Tool Intelligence

Distinguishes direct-execution from suggest-only tools. Missing tools detected with one-click install commands.

FEAT_06

Project Memory

Auto-saves engagement state as an AI-readable project.md. Resume any session exactly where you left off.

FEAT_07

Cheat Sheet Loader

Drop engagement notes in cheatsheets/ and the AI loads them for context. Add more at runtime with :cheat.

FEAT_08

Auto Reporting

Generate markdown reports with findings, command history, and results. Session state saved as JSON for review.

04
KILL CHAIN WORKFLOW

Engagement Phases

  1. Recon Nmap scans, service detection, OS fingerprinting. Quick scan (top 100) or full 65535-port sweep. Commands: :scan :fullscan
  2. Enumeration Service-specific checks triggered by detected ports. 49 checks across 14 services, plus directory busting and vuln scanning. Command: :svc <port>
  3. Initial Access Credential testing, exploit suggestions, SSH/WinRM connections. Chisel and ligolo-ng for pivoting. Commands: :ssh :cred
  4. Privilege Escalation 28 Linux checks and 21 Windows checks. linpeas, winPEAS, Potato exploits, kernel CVEs — all suggested with download links. Commands: :auto :tools
  5. Report Auto-generated markdown report with findings, command history, and results. Command: :report

SETUP

Quick Start

  1. Windows Host Setup Clone the repo and run the setup script. It pulls models, configures Ollama, and adds a firewall rule.
  2. Kali Client No pip dependencies — pure Python 3 stdlib. Connect to your Windows host's IP.
  3. Cloud API (Optional) Swap to OpenAI or Anthropic Claude when you need more capable reasoning.
Windows HOST
git clone https://github.com/sudoxs/xs-ai.git && cd xs-ai
.\host_setup.ps1
Kali CLIENT
git clone https://github.com/sudoxs/xs-ai.git && cd xs-ai
python3 client.py --host <WINDOWS_IP>
python3 client.py --host ignored --api openai --api-key sk-...
Use OpenAI instead of Ollama

AUTHORIZATION

Safety & Ethics

STEP 01

AI Suggests

The AI analyzes the current state and proposes a command or strategy. It never executes anything on its own.

STEP 02

You Approve

Review every suggestion. Edit, skip, or override. The operator is always the final authority.

STEP 03

It Runs

Only after explicit approval does the command execute. Full output is captured and fed back to the AI for the next step.

No Auto-Exploit XS-AI never fires an exploit without you pressing enter.
No Exfiltration No data leaves your engagement environment automatically.
No Scope Creep Target is locked at session start. AI stays within your defined scope.
No Credentials Sent API keys and credentials never leave your local machine.
Authorized use only. XS-AI is designed for authorized penetration testing engagements, CTF competitions, and security research. Always obtain proper written authorization before testing any system you do not own. The operator is responsible for all actions taken with this tool.
