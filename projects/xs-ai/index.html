OVERVIEW

What Is XS-AIXS-AI とは

XS-AI is a pure-Python pentest orchestrator that pairs AI reasoning with human judgment. It runs on Kali Linux and talks to an Ollama instance on your Windows host — or directly to OpenAI / Anthropic cloud APIs. XS-AI は、AIの推論と人間の判断を組み合わせた純Python製のペンテスト・オーケストレーターです。Kali Linux 上で動作し、Windows ホストの Ollama — あるいは OpenAI / Anthropic のクラウドAPIと直接通信します。

The AI suggests commands. You approve, edit, or skip every one. Nothing executes without explicit operator consent. Session state, findings, and command history are saved automatically so you can resume any engagement. AIはコマンドを提案します。そのすべてを、あなたが承認・編集・スキップします。 オペレーターの明示的な同意なしには何も実行されません。セッション状態・発見事項・コマンド履歴は自動保存され、いつでもエンゲージメントを再開できます。

CAPABILITIES

Features機能

FEAT_01

Human-in-the-Loopヒューマン・イン・ザ・ループ

Every command requires explicit operator approval. Edit, skip, or override any AI suggestion before it touches the target.すべてのコマンドにオペレーターの明示的な承認が必要です。ターゲットに触れる前に、AIの提案を編集・スキップ・上書きできます。

FEAT_02

Multi-Backend AIマルチバックエンドAI

Local Ollama models by default. Swap to OpenAI or Anthropic Claude with a single flag for more capable reasoning.デフォルトはローカルの Ollama モデル。フラグひとつで OpenAI や Anthropic Claude に切り替え、より高度な推論が可能です。

FEAT_03

14 Service Enumerators14種のサービス列挙

Port-aware enumeration for FTP, SSH, SMTP, DNS, HTTP, SMB, NFS, MSSQL, MySQL, RDP, WinRM, SNMP, Redis, and LDAP.FTP・SSH・SMTP・DNS・HTTP・SMB・NFS・MSSQL・MySQL・RDP・WinRM・SNMP・Redis・LDAP に対応したポート認識型の列挙。

FEAT_04

Role Mappingロール・マッピング

Assign different AI models to different phases. Route recon to a planner, access to an analyzer — full control over your model chain.フェーズごとに異なるAIモデルを割り当て。偵察はプランナーへ、アクセスはアナライザーへ — モデルチェーンを完全に制御できます。

FEAT_05

Tool Intelligenceツール・インテリジェンス

Distinguishes direct-execution from suggest-only tools. Missing tools detected with one-click install commands.直接実行ツールと提案のみのツールを区別。未インストールのツールを検出し、ワンクリックのインストールコマンドを提示します。

FEAT_06

Project Memoryプロジェクト・メモリ

Auto-saves engagement state as an AI-readable project.md. Resume any session exactly where you left off.エンゲージメント状態を、AIが読める project.md として自動保存。中断した地点からセッションを正確に再開できます。

FEAT_07

Cheat Sheet Loaderチートシート読み込み

Drop engagement notes in cheatsheets/ and the AI loads them for context. Add more at runtime with :cheat.cheatsheets/ にメモを置くと、AIがコンテキストとして読み込みます。実行中も :cheat で追加できます。

FEAT_08

Auto Reporting自動レポート

Generate markdown reports with findings, command history, and full command output. Session state auto-saved as JSON for review.発見事項・コマンド履歴・コマンドの全出力を含む Markdown レポートを生成。セッション状態は JSON として自動保存されます。

FEAT_09

Context Retrieval (RAG)コンテキスト検索 (RAG)

A pure-stdlib TF-IDF retriever feeds the model only the notes and evidence relevant to your current question — large note sets no longer flood a 7B model's context window.純標準ライブラリの TF-IDF リトリーバーが、現在の質問に関連するメモと証拠だけをモデルに渡します — 大量のメモでも 7B モデルのコンテキスト窓を溢れさせません。

FEAT_10

Output Distillation出力の蒸留

Huge nmap / enum4linux / linpeas output is condensed to signal-dense lines before the model sees it. The full raw output is always kept in the report and session JSON.巨大な nmap / enum4linux / linpeas の出力を、モデルに渡す前に重要な行へ凝縮。生の全出力は常にレポートとセッション JSON に保存されます。

FEAT_11

Structured JSON Output構造化JSON出力

Schema-constrained JSON responses cut format errors on small models, with a tolerant parser and automatic fallback to the legacy command protocol.スキーマ制約付きの JSON 応答で小型モデルの書式エラーを削減。寛容なパーサーと、従来のコマンドプロトコルへの自動フォールバックを備えます。

FEAT_12

Dynamic Discovery動的ディスカバリ

Unknown ports no longer get generic advice — xs-ai banner-grabs the service and asks the AI for tailored, read-only enumeration checks.未知のポートにもう汎用的な助言はしません — xs-ai がサービスのバナーを取得し、そのサービスに合わせた読み取り専用の列挙チェックをAIに尋ねます。

FEAT_13

Parallel Enumeration並列列挙

Run independent checks concurrently after a single batch approval — slow I/O-bound scans finish faster without breaking per-command approval.一括承認のあと、独立したチェックを同時実行 — コマンドごとの承認を崩さずに、遅いI/O待ちのスキャンを高速化します。

FEAT_14

Re-test Guard再テスト・ガード

xs-ai remembers every command already run. Before repeating one it warns and asks again, and :auto / :svc skip completed checks by default — add redo to force.実行済みのすべてのコマンドを記憶します。再実行の前に警告して再確認し、:auto / :svc は完了済みチェックを既定でスキップ — redo で強制できます。

FEAT_15

Engagement Handoffエンゲージメントの引き継ぎ

Export a self-contained bundle (history, findings, credentials, memory) with :export; another operator runs :import to merge it and continue — de-duplicated, and feeding their own re-test guard.:export で自己完結型のバンドル（履歴・発見事項・資格情報・メモ）を出力。別のオペレーターが :import で統合して続行できます — 重複排除され、相手の再テスト・ガードにも反映されます。

FEAT_16

Fail-Closed Scopeフェイルクローズ・スコープ

One central guard authorizes every target-touching route (CIDR/IP/host aware) and blocks commands embedding any out-of-scope IP. No scope configured means execution is blocked, with a full JSON audit trail.一つの中央ガードが、ターゲットに触れるすべての経路（CIDR/IP/ホスト対応）を認可し、スコープ外のIPを含むコマンドを遮断。スコープ未設定なら実行はブロックされ、完全な JSON 監査ログが残ります。

FEAT_17

Service Research Engineサービス調査エンジン

:research <port> fingerprints a service and produces ranked, evidence-based vulnerability hypotheses from an offline knowledge base (and NVD when online) — confidence and severity kept separate, CVEs never claimed from a product match alone.:research <port> がサービスをフィンガープリントし、オフライン知識ベース（オンライン時は NVD も）から根拠に基づく脆弱性仮説をランク付けして生成。confidence と severity を分離し、製品名の一致だけで CVE を断定しません。

FEAT_18

Safe Credential Validation安全な資格情報の検証

Five distinct auth states (no-auth / anonymous / default-possible / validated / unknown). :validate checks one documented credential or anonymous probe — approved, scoped, attempt-limited, recorded. No wordlists, no brute-force.5つの明確な認証状態（認証なし／匿名／デフォルト可能性／検証済み／不明）。:validate は文書化された単一の資格情報か匿名プローブを確認 — 承認・スコープ・試行回数制限・記録つき。ワードリストもブルートフォースもなし。

FEAT_19

Attack Chain Analysis攻撃チェーン分析

:chains links separate observations into coherent scenarios (exposed interface → weak auth → access → misconfig), stating the evidence, unverified assumptions, and potential impact — reasoned scenarios, never claims of exploitation.:chains が個別の観測を筋の通ったシナリオに連結（露出インターフェース → 弱い認証 → アクセス → 設定不備）。根拠・未検証の仮定・潜在的影響を明示 — あくまで推論シナリオで、攻撃の成功を主張しません。

FEAT_20

Multi-Model Registryマルチモデル・レジストリ

Declare any number of models (Ollama / OpenAI / Anthropic) with endpoints and capabilities; assign them to roles or auto-select by capability and context, with graceful fallback. Plus secure connection modes: direct, SSH tunnel, or VPN overlay.任意の数のモデル（Ollama / OpenAI / Anthropic）をエンドポイントと能力つきで宣言し、ロールに割り当てるか能力とコンテキストで自動選択（フォールバック付き）。さらに安全な接続モード：direct・SSH トンネル・VPN オーバーレイ。

FEAT_21

Quality Benchmark品質ベンチマーク

An offline, deterministic benchmark scores the engine's logic — service ID, CVE relevance, false-positive reduction, evidence quality, reporting accuracy — as a CI regression gate, not by how convincing a model sounds.オフラインで決定論的なベンチマークが、エンジンのロジック（サービス識別・CVE 関連性・誤検知削減・根拠の質・レポート精度）を採点。モデルの説得力ではなく、CI の回帰ゲートとして機能します。

AUTHORIZATION

Safety & Ethics安全性と倫理

STEP 01

AI SuggestsAIが提案

The AI analyzes the current state and proposes a command or strategy. It never executes anything on its own.AIは現在の状況を分析し、コマンドや戦略を提案します。自ら実行することは決してありません。

STEP 02

You Approveあなたが承認

Review every suggestion. Edit, skip, or override. The operator is always the final authority.すべての提案を確認し、編集・スキップ・上書きします。最終的な決定権は常にオペレーターにあります。

STEP 03

It Runs実行される
